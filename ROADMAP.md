# Roadmap

Every task in [PLAN.md](docs/PLAN.md) has an implementation on this branch. These are what is left, in suggested order. Each one was checked against the code on this branch.

1. Rolling updates on one machine. On a single node every move of an app without routes is in place, so each replica is down while its new container starts, whether or not the app publishes a host port. This is closed for routed apps only: an app with `routes` and no host ports publishes its route ports on host ports the agent picks, from 30000 to 32767, so its update starts each new copy beside the old one, on the same node too (see [routing](docs/routing.md#rolling-updates)). The same surge on the replica's own node would close the gap for an app with no host port. Two copies of an app that publishes a fixed host port can't share a node, so such an app keeps the gap on one machine.
2. Host ports in a rolling update. A put or a scale now lists the replicas no node took, with the app that holds their host port, and `deploy --wait` fails at once for one that cannot get a node by itself (see [placement](docs/concepts.md#placement)); the write itself is still accepted. A change to the spec of an app whose replicas run is not checked that way: its rollout moves each replica later, and a move in place onto a node where another app publishes the new host port has its container refused by Docker there, so the rollout pauses at the move's deadline, and the put's reply said nothing of it. The put could check the new spec's host ports against each replica's node.
3. A web UI, if one is wanted. The API has what a browser needs for Task 6: login and logout at `/v1/session`, a session cookie, and CSRF checks on unsafe requests. There are no pages.
4. Routing beyond exact hosts: wildcard hosts, which need a DNS-01 challenge for their certificates, and TCP routes. Both are refused today. Path prefixes are done (see [routing](docs/routing.md#paths)), and so are HTTP/2 and gRPC to the replicas, over h2c (see [protocols](docs/routing.md#protocols)).
